The System Before the Prompt.

Essay

answer once

You paste a careful brief into Claude, and it still hands back a screen with the wrong button, a colour it invented, and a column that ends halfway across the page. The brief was fine. Here is the layer I put under the brief, and what it stopped costing me.

The six steps had a gap of their own

I wrote before about the prompt I paste before every prototype (opens in a new tab). Personas, then a service blueprint, then the information architecture, then text wireframes, then the real content, and only then the build. The argument was about order: each step is roughly ten times cheaper to change than the one after it, so spend your opinions where they are cheap. And every gap you leave in the brief gets filled by the most average assumption available.

This is the follow-up, because the six steps had a gap of their own, and the model filled it exactly the way that piece warned.

The sequence decides what the product is. Who it is for, what they do, what the screen says. It does not decide what anything looks like. So when the build step arrived, Claude met a thousand small visual questions the brief had never answered. What colour is a primary button? How wide is a reading column? What happens on hover? How much space sits between two sections?

It answered every one. Reasonably, on each page, from scratch.

I expected the careful brief to carry through to the build. What I got instead was a site that was right about the product and wrong about itself in a hundred small ways, a different one on each page. That was my miss. I had treated the look as something the build would settle, when the look is a set of decisions like any other, and I had left all of them to the most average assumption available.

What “average assumption” costs, counted

I have the numbers because the site checks itself.

None of these is a model being stupid. Each is a model being asked the same question forty times and giving forty reasonable answers. The fault was upstream.

Nobody had answered once. So the model answered every time.

The system is step zero

So the design system moved from a nice-to-have at the end to the thing that exists before the first prompt. Not a style guide the model might read. A set of files the model cannot build without. Three things make it work as a constraint rather than a suggestion.

The values are generated, not picked. Seven colour families, ten stops each, evenly spaced in perceived lightness. That single choice makes one rule true across the palette: stop 600 carries a word, and it measures between 4.59 and 5.23 to 1 on paper. Claude no longer chooses a text colour. It chooses a role, and the role has already been measured.

The stylesheet is layered, and the model writes into the last layer. It is divided into eight compartments in a fixed order, and a later compartment wins regardless of how specific the rule is or where it sits in the file. Every rule the site adds goes into the final one. This ended a whole class of argument where a correct rule lost to an identical one two thousand lines away.

The build refuses what the system did not define. If a rule points at a value that does not exist, the build fails. Components may read only the values meant for components, and a check asserts it. On the first pass, the layer written specifically to obey that rule still leaked reads from the wrong tier. The check found them. A reviewer would not have.

Then teach the model the rules the values cannot hold

The values carry the numbers. They do not carry the judgement. So the system ships as a Claude plugin with two skills: the system itself, and the ten checks that decide whether a change may ship.

The system skill carries what is invisible in the values. Colour is semantic, never decorative. A component declares its own ink on its own ground rather than inheriting and hoping. Never state a contrast ratio you have not measured on rendered pixels, because gradient text and translucent tints both lie to any check that reads styles instead of paint. And the one I wrote after the most rework: a capped column inside a wider container is a defect, not a style. Whitespace has to be designed, not left over.

The checks skill carries the discipline: plant a defect, watch the check go red, then trust it. Refuse to report on zero measurements. Treat an impossible reading as your instrument breaking, not the product.

Install it, ask for a component, and the model already knows all of that before it draws. The work that comes back is on-system, instead of work someone has to correct afterwards.

What it saved, honestly

I cannot give you a before-and-after in hours, because I did not time the rework before the system existed. What I can give you is the shape of the change. Before, every review found the same class of defect on a new page, and every fix was one page. After, a defect is a missing rule, the fix is one line in the system, and the build carries it to every page at once.

There is a fair objection here: this is a lot of infrastructure for one person’s website. It is. But the site is the small case. The pattern came from a client where six products had grown one at a time and looked like six companies had made them. One system across the line, then encoded as a plugin so it stopped depending on who remembered it. That is on the record in the AdTech case, and the plugin on my site exists because the client’s version is confidential and a claim with no artifact behind it is just a claim.

Where this breaks

A system does not decide whether the component is the right component, whether a layout is good, or whether a colour is beautiful. Its checks say so in their own output. Composition, the thing a reader sees when two elements sit beside each other, still needs an eye and a rendered page at four widths. The system takes the thousand small questions off the table so that eye can spend itself on the ten that matter.

Add this before your step one

If you use the six-step brief, put this in front of it. Before personas, hand the model the system: the values, the layers, the rules the values cannot hold, and the checks. If you do not have one, the first prototype will tell you exactly which decisions you forgot to make, because the model will have made all of them for you.

The half-second of doubt is the only thing I design.
